# Self-hosting

`nh.nh` describes the `.nh` language in `.nh`. A parser generated from it parses
**every `.nh` file in this repository**, including itself.

```console
$ cargo test -p nh-lower --test selfhost
```

## What is and is not claimed

DESIGN.md's M6 asked for `nh.nh` to *reproduce* `nh.pest`. That was unreachable
when written, and saying so was more useful than pretending otherwise. `nh.pest`
used three constructs `.nh` could not express:

| `nh.pest` | Status in `.nh` |
|---|---|
| `item = _{ a \| b }` | **Now expressible** — `silent rule item = a \| b;`. Not used here: this grammar binds almost everything, and a silent rule produces no node to bind |
| `string = ${ "\"" ~ inner ~ "\"" }` | **Now expressible** — a `token` without `@` is compound-atomic |
| `ASCII_HEX_DIGIT{1,6}` | **Still missing.** `.nh` has `*`, `+`, `?` and no `{n,m}` |

Two of the three have since been closed — `silent rule` and compound-atomic
tokens both exist now, added because writing this grammar is what showed they
were missing. Only bounded repetition remains, and none of them affects which
*strings* are accepted. So the achievable and meaningful property is **language
equivalence**, and that is what the test checks.

## What writing it revealed

This is the real value of the exercise. Two findings, both about `.nh` rather
than about pest.

### The gaps became features

Everything in the table above except bounded repetition was closed *because*
this grammar needed it. That is the argument for self-hosting: writing a
language in itself is the only exercise that finds what it cannot say.

`guard from`, `silent rule`, and compound-atomic tokens all exist because
writing `nh.nh` made their absence concrete.

### `reserved from` does two things, and sometimes you want one

`.nh` reserves nothing globally — `atom` is both a precedence-block keyword and
a perfectly ordinary rule name, and every grammar in this repo contains
`rule atom = ...`. Ordered choice over distinct leading keywords resolves it.

But `reserved from IDENT { "atom" }` would *both* boundary-guard the literal
**and** forbid it as an identifier. Only the first is wanted here, and `.nh` has
no way to ask for it alone. The first draft of this grammar reserved the
keywords and immediately rejected `rule atom = primary;` — a line that appears
in nearly every `.nh` file in the repo.

That gap is now closed: `guard from IDENT { .. }` is exactly the half that was
wanted, and the 29 hand-written guards in this file collapsed to one
declaration.

### The M0 keyword bug reappears one level up

The hand-written guards were first written as rules:

```nh
rule kw_grammar = "grammar" !IDENT_TAIL -> kw;    // WRONG
```

That silently fails. A rule is non-atomic, so pest inserts implicit whitespace
between the literal and the lookahead; the guard then tests the *following*
identifier, matches it, and fails. Every keyword-led rule stops parsing.

This is **the same defect that broke `nh.pest` during M0** (DESIGN.md §2),
reproduced faithfully the moment a user hand-writes a guard in `.nh`. The fix is
to make them atomic tokens:

```nh
token KW_GRAMMAR = @ "grammar" !IDENT_TAIL;       // right
```

Nothing in the language stops you writing the broken form, and the resulting
error points nowhere near the cause. That is the strongest argument the project
has produced for generating these guards rather than documenting them.

## Layout

| | |
|---|---|
| `nh.nh` | The grammar |
| `nh.pest` | Generated by `nh build`. Not compared against the hand-written `crates/nh-syntax/src/nh.pest` — see above |

The test that matters lives in `crates/nh-lower/tests/selfhost.rs`. It walks the
repository for `.nh` files rather than listing them, so a new grammar is covered
automatically.
