# Worked example: a config language interpreter

This exists to test one claim from `DESIGN.md`: that a language can be
implemented across **many small files** with **no positional access** to the
parse tree.

```console
$ cargo run -p config-example -- examples/config/sample.conf
{name: "nailhammer", version: 0.2, stable: false, notes: null, tags: [...], limits: {...}}
```

## What is hand-written vs generated

| | |
|---|---|
| `config.nh` | The grammar. The only file describing the language |
| `src/handlers/*.rs` | **Yours.** One small file per grammar alternative |
| `src/value.rs`, `src/lib.rs` | Yours. The value type and the host struct |
| `src/config.pest` | Generated by `nh build` |
| `src/generated/**` | Generated. The trait stack, dispatch, views, `Place` |

Regenerate with:

```console
$ nh build config.nh -o src/config.pest --rust src
```

Handler files are written **once** and never overwritten, so re-running is safe.

## The point

Here is the whole `entry` handler:

```rust
pub fn run(_host: &mut Interp, key: &str, value: Value, _cx: &mut Ctx) -> Result<Value> {
    Ok(Value::Field(key.to_string(), Box::new(value)))
}
```

`key` and `value` are the bindings in
`rule entry = key:IDENT "=" value:value ";" -> entry;`, in that order. The
generated dispatch walked the tree and evaluated `value` before calling this.
Four properties follow:

- **There is no parse tree here.** Nothing to traverse, nothing to fetch, no
  `into_inner()` and no child indexing.
- **Reorder the grammar and this file does not change.** Bindings are matched by
  name, not position.
- **Renaming a binding is a compile error**, not a silent misparse. Change
  `key:` to `name:` in the grammar, regenerate, and the parameter goes with it.
- **Cardinality is in the type.** `entries:entry*` gives `Vec<Value>`;
  `tail:else_tail?` gives `Option<Value>`. Change `*` to `?` in the grammar and
  the handler stops compiling.

Errors need no span threading:

```rust
Err(_) => cx.err("not a valid number"),
```

`dispatch` wraps every handler call in `cx.scoped(..)`, so `cx.err` already
knows which node it is inside.

## Why no arithmetic

This language deliberately has **no operator table**. The operator driver —
precedence climbing, laziness, `Thunk` — is milestone M3. An example that needed
it could not run yet, so this one exercises dispatch, spans, and
one-file-per-rule on their own.

## Adding an alternative

Try it. Add to `config.nh`:

```nh
  | "[" items:value* "]" "!" -> excited
```

Then `nh build config.nh -o src/config.pest --rust src` and `cargo build`. The
build fails: `Handlers` gained a required `value_excited` method, and the
generated stub is waiting in `src/handlers/value_excited.rs` — already carrying
`items: Vec<Value>` as a parameter, documented, with a `compile_error!` where
the body goes. Nothing silently does the wrong thing.
