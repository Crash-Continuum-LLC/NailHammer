# {{name}}

A language built with
[NailHammer](https://github.com/Crash-Continuum-LLC/NailHammer).

## Run it

```console
$ cargo run                    # runs sample.{{ext}}
$ cargo run -- other.{{ext}}
```

It works, it is not a skeleton: variables, arithmetic with real precedence,
branches, printing and error recovery — plus loops and functions if you asked
for them.

By default this is a **compiler**: handlers emit three-address code for a
register machine, and `cargo run` prints the instructions before running them.
`nh init --interpreter` scaffolds a tree-walker instead, where handlers return
values.

## The loop

```console
$ $EDITOR {{name}}.nh                                        # 1. edit the grammar
$ nh check {{name}}.nh                                       # 2. fast feedback
$ nh build {{name}}.nh -o src/{{name}}.pest --rust src       # 3. regenerate
$ cargo run                                                  # 4. run it
```

`nh check` runs the same analysis `build` does — including the determinism
lints — so it will not pass a grammar that `build` would reject. And `build.rs`
already does step 3 for you: `cargo run` regenerates whenever the `.nh` changes.

## Seeing where a program goes

```console
$ nh trace {{name}}.nh --source 'print 1 + 2 * 3;'
```

Which handler each part of a program reaches, what it receives, and which
arguments have **not** been evaluated yet. Nothing is compiled — your grammar is
interpreted — so it costs a parse rather than a build.

Operators are shown folded the way the driver folds them, which is the one thing
nothing else can tell you: precedence lives in the operator table, so the parse
tree is flat and has no order in it.

The VS Code extension puts this in a live pane beside your grammar.

## Layout

| Path | |
|---|---|
| `{{name}}.nh` | **The grammar.** The only description of your language |
| `src/handlers/*.rs` | **Yours.** One small file per grammar alternative |
| `src/lib.rs` | Yours. The value type (or the instruction set) and operator semantics |
| `src/main.rs` | Yours. Where source comes from, and where errors go |
| `src/generated/**` | Generated. Views, dispatch, diagnostics — never edit |
| `src/{{name}}.pest` | Generated by `nh build` |

`nh build --rust` **never overwrites a handler file.** New alternatives get a
stub; existing handlers are left alone.

## How it fits together

A handler's parameters *are* its bindings. There is no parse tree to walk:

```rust
// handlers/stmt_bind.rs — from `"let" name:IDENT "=" value:expr ";" -> bind`
pub fn run(host: &mut Interp, name: &str, value: Value, _cx: &mut Ctx) -> Result<Value> {
    host.set(name, value.clone());
    Ok(value)
}
```

A token binding arrives as text, a rule binding arrives **already evaluated**,
and the generated dispatch did the walking.

- **No positional access.** Reorder the grammar and this file does not change.
- **Renaming a binding is a compile error**, not a silent misparse.
- **Cardinality is in the type.** `stmts:stmt*` gives `Vec`; `x:y?` gives
  `Option`. Change `*` to `?` and the handler stops compiling.
- **Adding an alternative breaks the build** until a handler exists.

## What `main.rs` does, and does not

Three things are yours, because only your program knows them: where the source
comes from, what to do with a result, and where errors go.

Everything between — parse, report a parse error, collect the syntax errors
recovery got past, build the owned tree, evaluate — is `generated::eval_source`.
That sequence has one correct order and is the same in every project, so you are
not asked to write it.

```rust
match generated::eval_source(&mut interp, &mut cx, file) { .. }
```

`Ok` means the program was clean. A parse that *recovered* comes back as `Err`
holding the syntax errors, even though everything evaluable was evaluated — a
reported typo is not a successful run. Whatever your handlers collected is still
on your host, so a partial run can still show its output, and the scaffold prints
it either way.

## Things that bite people

**Anchor your entry rule.** `rule program = SOI stmt* EOI;` — implicit skipping
happens *between* elements, never before the first, so without `SOI` a program
starting with a blank line will not parse.

**Leave `grammar-extras` on.** Without it every node tag is silently ignored:
the grammar compiles, parsing succeeds, and every accessor returns nothing with
nothing pointing at the cause. Already set in `Cargo.toml`.

**There is no `expr` rule, deliberately.** It comes from `use operators::core`.
Your grammar supplies `atom`; run `nh explain {{name}}.nh` to see the precedence
table you got.

**Declare keywords with `reserved from`.** It guards both directions — `let`
will not match inside `letter`, *and* `let` cannot be a variable name.

## Try changing something

- **Add an operator.** Put `right "**" above "*" -> pow;` in a
  `precedence override { }` block, implement `pow` in `src/lib.rs`, done.
- **Add `+=`.** Add `right "+=" below "=" -> assign;`. Nothing else — the
  compound-assignment default is written in terms of `assign` and `place_read`.
- **Add a statement.** Add an alternative with a `-> label`, regenerate, and
  the build will fail until you write its handler. The stub is waiting for you
  with its accessors listed.
- **Break the sample.** Put `@@@ ;` on a line. Recovery reports it and carries
  on to the next `;`, so later errors still show.
